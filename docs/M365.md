# Microsoft 365 mailbox integration

This stack reads DMARC reports from one dedicated Exchange Online mailbox. Do not use a personal mailbox or a shared inbox that also contains regular business mail.

## 1. Prepare the mailbox

Create `dmarc-reports@example.com` as a shared mailbox or licensed service mailbox. Create these folders before starting parsedmarc:

- `Inbox/DMARC` for incoming reports
- `Inbox/DMARC/Processed` for successfully processed reports

Route the DMARC aggregate-report address to this mailbox. Keep the mailbox out of normal user workflows.

## 2. Create the app identity

Create a single-tenant Entra ID App Registration named `parsedmarc-dmarc-reader`. Record:

- Application (client) ID
- Directory (tenant) ID
- Enterprise application service principal **Object ID**

The current connection UI supports application authentication with a Client
Secret. Give the secret an owner, a short defined lifetime and a documented
rotation procedure. Certificate authentication is a planned extension, not a
currently available option in this UI.

## 3. Restrict access with Exchange Application RBAC

Application RBAC is the recommended scope mechanism for a new setup. The person configuring this needs the appropriate Exchange Online permissions.

1. Create a mail-enabled security group and add the DMARC mailbox as a **direct** member.
2. Create an Exchange management scope for that group.
3. Create the Exchange pointer to the Entra service principal and assign `Application Mail.ReadWrite` only within that scope.
4. Verify the assignment against the DMARC mailbox before starting the container.

The following is an outline; replace all placeholders and validate the group distinguished name with your Exchange administrator:

```powershell
Connect-ExchangeOnline

$appId = '<application-client-id>'
$objectId = '<enterprise-application-service-principal-object-id>'
$groupDn = '<mail-enabled-security-group-distinguished-name>'

New-ManagementScope -Name 'Parsedmarc DMARC mailbox' `
  -RecipientRestrictionFilter "MemberOfGroup -eq '$groupDn'"

New-ServicePrincipal -AppId $appId -ObjectId $objectId -DisplayName 'parsedmarc-dmarc-reader'

New-ManagementRoleAssignment -Name 'parsedmarc Mail.ReadWrite' `
  -Role 'Application Mail.ReadWrite' `
  -App $appId `
  -CustomResourceScope 'Parsedmarc DMARC mailbox'

Test-ServicePrincipalAuthorization -Identity $appId `
  -Resource dmarc-reports@example.com
```

Do not additionally grant tenant-wide `Mail.ReadWrite` in Entra ID: such grants are additive and would defeat the intended mailbox scope. If an organisation still uses Application Access Policies, keep that legacy configuration separate and document it as an exception; do not combine both models for the same permission.

## 4. Configure, test and activate the connection

Open **DMARC Control → Settings → Mailbox connection** and sign in as
administrator.
Select Microsoft 365 and enter the tenant ID, application client ID, Client
Secret, mailbox, reports folder and archive folder.

1. Save the values as a new draft.
2. Run **Test connection**. This obtains an application token and checks the
   specified folders with Graph `GET` requests only. It does not list or read
   messages and never moves, changes or deletes one.
3. Verify that the app cannot access a mailbox outside the RBAC scope.
4. Explicitly activate the successfully tested revision.

Only activation hands the revision to the single parser supervisor. During a
change it stops the previous parsedmarc child before starting the replacement.
The runtime configuration keeps `delete = False`, archives successfully
processed messages in the configured archive folder and never launches a
second mailbox consumer.

An existing `config/parsedmarc.ini` remains a legacy fallback until the first
GUI-managed connection has been activated. New installations do not need that
file.

## Operational ownership

Record the mailbox owner, app owner, certificate/secret expiry, group membership, retention for the processed folder, and the break-glass procedure. Alert if no aggregate report is processed for the agreed threshold, for example 48 hours.
